# 记账App - 验证清单

## 数据层验证
- [x] 数据库可正常创建，三张表（expense、income、category_memory）结构正确
- [x] 首次启动自动写入种子记忆数据，category_memory 表中有数据
- [x] 种子数据使用 INSERT OR IGNORE，不会覆盖已有记忆
- [x] 多次重启App，种子记忆条数不增长，确认不会重复插入
- [x] 金额字段为 Long（分），存储和读取无精度问题
- [x] triggerWord + type 联合唯一索引生效，重复记录被覆盖更新
- [x] expense/income 表的 time 字段有索引
- [x] 禁用 fallbackToDestructiveMigration()，代码中不存在此方法调用

## 核心流程验证
- [x] 自然语言输入后，AI解析成功，记账卡片正确展示
- [x] 包含已记忆触发词的输入，自动命中记忆，分类锁死，置信度1.0
- [x] 记忆命中后 AI 仅补全金额/时间/商家，不返回分类字段
- [x] 即使 AI 返回错误分类，最终入库分类仍为记忆值，绝不覆盖
- [x] 收入关键词（发工资等）正确识别为 income 类型
- [x] 默认无收入关键词时识别为 expense 类型
- [x] 用户修改分类后，记忆表正确写入/更新
- [x] 用户修改分类后按 type+触发词 upsert 新记忆（设计简化：修改弹窗仅改分类不改 type，避免跨表迁移复杂度，已在项目记忆中记录为接受方案）
- [x] 手动记账表单提交后，数据正确入库
- [x] 删除记录后，数据从表中移除
- [x] 记账成功后对应记忆的 hitCount 才 +1
- [x] 预判 type 偏差时，AI 返回最终 type 后兜底匹配记忆（如"发红包"预判为支出，AI 判定为收入后仍可命中收入类记忆）
- [x] 商家为空时修改分类/手动记账，记忆表不新增条目（避免无意义通用词污染记忆库）
- [x] API Key 为空或为默认值时，不发起网络请求，直接提示用户配置
