# 2026-07-06-分类系统数据库化设计

## 概述

将分类体系从硬编码常量彻底改造为数据库存储，实现分类的动态管理和编辑能力。同时修复分类记忆管理中新增记忆时分类选择使用文本输入的问题，改为从系统分类中下拉选择。

## 核心问题

1. **分类硬编码**：`CategoryConstants.kt` 中的分类数据是固定常量，无法动态编辑
2. **分类选择体验差**：`AddMemoryDialog` 使用文本输入分类，容易出错且不统一
3. **记忆关联脆弱**：`CategoryMemoryEntity` 使用分类名称字符串关联，无法应对分类重命名

## 设计目标

1. 分类体系完全数据库化，支持新增、编辑、删除分类
2. 分类选择统一使用下拉选择，从数据库动态加载
3. 记忆关联改为引用分类ID，支持分类重命名
4. 系统预置分类与用户自定义分类物理隔离

## 数据模型

### CategoryEntity

```kotlin
@Entity(tableName = "categories")
data class CategoryEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val type: String,           // expense / income
    val name: String,           // 分类名称
    val parentId: Long?,        // 父分类ID（null为一级分类）
    val sortOrder: Int,         // 排序
    val isSystem: Boolean,      // 是否系统预置
    val createdAt: Long,
    val updatedAt: Long
)
```

**索引设计**：
- `idx_categories_name_type_parent`: UNIQUE(name, type, parentId) — 确保分类名唯一

### CategoryMemoryEntity（修改）

```kotlin
@Entity(tableName = "category_memory")
data class CategoryMemoryEntity(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val triggerWord: String,
    val type: String,
    val categoryId: Long,       // 引用分类ID
    val subcategoryId: Long?,   // 引用子分类ID
    val hitCount: Int = 1,
    val source: String = "user",
    val confidence: Int = 100,
    val createdAt: Long,
    val updatedAt: Long
)
```

## 接口设计

### CategoryService

```kotlin
interface CategoryService {
    // 查询一级分类
    suspend fun getRootCategories(type: String): List<CategoryEntity>
    
    // 查询二级分类
    suspend fun getSubcategories(parentId: Long): List<CategoryEntity>
    
    // 根据ID查询分类
    suspend fun getCategoryById(id: Long): CategoryEntity?
    
    // 根据名称查询分类
    suspend fun getCategoryByName(type: String, name: String): CategoryEntity?
    
    // 核心匹配：输入文本 → 匹配分类
    suspend fun matchCategory(input: String, type: String): Pair<CategoryEntity, CategoryEntity?>?
    
    // 新增分类
    suspend fun addCategory(category: CategoryEntity): Long
    
    // 更新分类
    suspend fun updateCategory(category: CategoryEntity)
    
    // 删除分类（仅用户分类）
    suspend fun deleteCategory(id: Long)
}
```

## 迁移策略

### 数据库版本 3 → 4

1. 创建 `categories` 表
2. 创建索引 `idx_categories_name_type_parent`
3. 批量插入所有当前硬编码的分类数据（支出9个一级分类 + 子分类，收入8个一级分类 + 子分类）
4. 迁移 `category_memory` 表：将 `category` 和 `subcategory` 字符串字段转换为 `categoryId` 和 `subcategoryId`

## 物理隔离

- **AiPlanner**：只接收分类名称字符串作为提示，不直接依赖 CategoryService
- **分类匹配**：由 CategoryService.matchCategory() 统一处理，返回分类对象
- **CategoryConstants**：移除硬编码分类数据，仅保留辅助方法和常量定义

## 风险评估

1. **数据迁移风险**：category_memory 表的分类名称转ID需要确保映射正确
2. **兼容性风险**：需要确保所有引用分类的地方都能正确处理ID变化
3. **性能风险**：分类查询需要考虑缓存策略，避免每次查询都访问数据库
