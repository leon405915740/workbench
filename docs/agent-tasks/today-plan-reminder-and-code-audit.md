# 今日计划时间、到点提醒与全项目代码审查任务

## 项目定位

- 实际项目根目录：`D:\项目`
- 产品：Android 多模块应用「工作台」（`applicationId = com.aigrowth.os`）
- 正式「今日计划」实现：`app/src/main/java/com/aigrowth/os/feature/plan/`
- 业务数据：`core/database/src/main/java/com/aigrowth/os/core/database/workbench/`
- 网页原型 `猫咪生活报/workbench-desktop.html` 与 `android-ui-mockups/` 只作参考，不作为正式实现目标。

## 目标

1. 给「今日计划」的新增/编辑流程增加可选的计划时间。
2. 设置时间后，在计划日期与时间到达时发送本地通知；清除时间则不提醒。
3. 计划被编辑、完成、取消完成、删除，或设备重启、应用升级、精确闹钟权限获批时，提醒状态与数据库保持一致。
4. 对整个 Gradle 多模块项目执行潜在 Bug、Kotlin 类型、Android Lint、自动化测试、构建和代码安全审查；对范围明确、风险可控的问题直接修复。

## 行为要求

- 时间为可空字段，格式化显示为 `HH:mm`，不强制已有或新计划设置时间。
- 编辑器复用 Android 原生时间选择器，不引入新依赖；支持重新选择和清除时间。
- 日期必须是有效的 `yyyy-MM-dd`，标题不能为空；无效输入不得写入数据库或触发崩溃。
- 设置时间即表示启用提醒：
  - 保存未来时间：安排闹钟。
  - 修改日期、时间或标题：用同一计划 ID 更新闹钟内容与触发时刻。
  - 清除时间、完成计划或删除计划：取消闹钟。
  - 取消完成：仅当计划时间仍在未来时重新安排。
  - 过去时间不补发、不创建新闹钟。
- 使用项目已有的 Android 原生 `AlarmManager + BroadcastReceiver + NotificationManager` 路径。
- Android 12+ 在获得“闹钟和提醒”特殊权限时使用精确闹钟；未获批时保存计划不失败，并明确告知用户，同时用系统允许的非精确闲置闹钟作为降级。
- 设备重启、应用替换安装以及精确闹钟权限获批后，从 Room 中恢复所有仍未完成、仍在未来的提醒。
- 通知接收器不得对外暴露；通知只包含计划标题，不包含备注、图片路径或其他敏感内容。

## 验收标准

- 今日计划卡片能显示已设置的时间，编辑器能选择、修改、清除时间。
- 保存后数据库数据正确，未来提醒被安排；完成、清除时间、删除后提醒被取消。
- 通知具备独立计划身份，不会因多个计划互相覆盖；点击通知可回到工作台。
- 重启/应用升级/精确闹钟权限获批后的提醒恢复逻辑可编译并有可定位证据。

## 完成记录（2026-09-03）

### 今日计划与提醒

- `PlanItem.planTime` 采用可空 `HH:mm`；Room 数据库升级到 v4，以显式 3→4 迁移新增 `TEXT` 列，并回填旧完成计划缺失的 `completedAt`。
- 编辑器使用 Android 原生 `TimePickerDialog`，支持选择、修改和清除时间；界面与 ViewModel 写入口都校验标题、优先级、日期和时间。
- 每条计划以计划 UUID 构造唯一、不可变的广播 `PendingIntent`。新增/编辑/取消完成会按未来时间安排，完成/删除/清除时间会取消，过去时间不会补发。
- Android 12+ 在允许精确闹钟时使用 `setExactAndAllowWhileIdle`；否则降级为 `setAndAllowWhileIdle` 并引导用户进入系统“闹钟和提醒”授权页。授权、重启、应用替换、系统时间或时区变化后会从 Room 恢复候选提醒。
- Receiver 发通知前重新读取数据库并复核存在性、完成状态和触发时间；恢复 Receiver 不对第三方应用导出；通知仅显示计划标题，多计划以通知 tag 隔离。

### 审查中已修复

- 今日统计此前按 `completedAt` 计数而非真实 `done` 状态；迁移同步修复旧完成数据。
- 首页/计划页的“今天”值只在 ViewModel 创建时计算，跨午夜后不刷新；现改为日期流，并避免把其他日期的置顶计划误放进今日聚焦。
- 非法计划日期会使记录保存后从界面消失；现由 UI 与 ViewModel 双层严格校验。
- Alarm 唤醒冷启动时若在 Application 并发重排会撤销刚发出的通知；恢复逻辑移至明确的页面/系统事件入口。
- 多通知曾可能依赖 `String.hashCode()` 冲突；现以计划 UUID 作为通知 tag。
- 提醒恢复 Receiver 曾可被外部显式拉起；现设为 `exported=false`。
- 提醒恢复重排曾会顺带删除已经显示的到点通知；现把“取消闹钟”和“撤销通知”分开，系统恢复只重排闹钟，完成/删除/清除时间才同时撤销通知。
- 历史自定义优先级计划曾因新增的 P0/P1/P2 表单校验而无法完成、置顶或编辑；现仅新增表单限制三档，已存记录仍可正常操作。
- AI HTTP 响应未关闭导致连接池泄漏；现用 `Response.use` 关闭。
- 记账模块 Release 构建曾记录 HTTP BODY/请求头；现只在 Debug 启用 BASIC 日志并脱敏 Authorization，移除 APK 中未使用的编译期 API Key，并删除无调用且带错误重试实现的重复 Retrofit 客户端。
- 记账崩溃日志使用硬编码版本/调试状态；现读取宿主应用实际包信息。
- 记账纯逻辑测试被未使用的主线程 Handler 阻断；现移除 Looper 依赖，并在日志未初始化时安全静默。
- 记账时段规则会重新生成迁移前的“餐饮”旧分类；现统一为“餐饮美食”，同时兼容旧 AI hint。
- 中文整数金额未按产品契约解析、空描述未过滤、商户片段残留“昨天/花了”；现补齐并由测试覆盖。
- 元转分使用浮点乘法可能少 1 分，中文/AI 超大金额及多笔合计还可能溢出或饱和；现统一按“分”的 `Long` 与 `BigDecimal`/精确整数运算换算，拒绝溢出、非法中文角分速记和总额不一致。
- 多笔 AI 结果曾会静默丢掉无效条目后只记剩余部分；现任一条非法即整批失败，不再产生无提示漏记。
- 记账开机恢复 Receiver 曾对第三方应用导出；现改为 `exported=false`，通知监听服务仍由系统绑定权限保护。
- 银行 BigText 通知的 `EXTRA_TEXT` 可能只到“消费”的“消”，旧实现因此误判为非支出；现统一合并并去重标题、短正文、BigText 和文本行，再用同一完整内容执行支付、方向、去重与金额提取，且不放宽模糊关键词。
- `7.12人民币` 此前不会被日志金额规则遮盖；现统一脱敏“人民币/元/分”金额并保留无单位订单号，已有 JVM 回归测试。
